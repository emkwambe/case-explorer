# Challenge-mode scoring

_Generated by `node scripts/challenge-docs.mjs --write` from `src/challenge/score.js` and `teaching-v1` (SHA-256 `4f6884254c4e00b7a65a9b6b086472e76fb8743b84d05af5ca8bc88360102330`). The worked examples are scored by the code; `npm run test:challenge` asserts them._

A learner works a teaching case blind, then commits a decision, the reason codes and the strongest evidence. `scoreAttempt(teachingCase, attempt)` in `src/challenge/score.js` scores the attempt against the teaching answer (`expected`), never against the engine. It is a pure function: the same case and attempt always give the same score. No model or LLM is involved.

## 100 points

| Part | Points |
|---|---|
| Decision | 50 |
| Reason codes | 30 |
| Evidence | 20 |

A case is **passed at 70 or more**. Decision accuracy is reported on its own as well, so "right decision, weak reasons" reads differently from "wrong decision".

## Decision: 50 points

| Expected ↓ / Chosen → | Approve | Review | Decline |
|---|---|---|---|
| **Approve** | 50 | 20 | 0 |
| **Review** | 0 | 50 | 20 |
| **Decline** | 0 | 25 | 50 |

Approving a case that needed checking is the costliest error, so it scores zero. Declining a good applicant also scores zero: it turns away creditworthy business and triggers an adverse-action notice. Sending a decline case to review is the safe miss, so it gets partial credit (25); sending an approve case to review costs operational time, so it gets less (20). Declining a case that needed review scores 20: the case was not safe to approve, but a decline without verification is still a wrong outcome.

## Reason codes: 30 points

`30 × (required codes chosen ÷ required codes) − 10 × (chosen codes that are neither required nor acceptable)`, floored at 0.

- **No codes required** (a clean approval): coverage is full, so choosing none scores 30; each extra code still costs 10.
- **Acceptable codes** (`expected.acceptable_codes`): not wrong, not required. They earn nothing and cost nothing. On concealment pairs 1 to 3, FRAUD_REVIEW is acceptable: referring the case is not wrong, only incomplete.
- Choosing a code twice counts once.

The codes a learner can choose are every code `teaching-v1` uses:

| Code | Meaning |
|---|---|
| LOW_FICO | The credit score is below the program minimum of 660. |
| ELEVATED_DTI | Debt-to-income is in the watch band (36% to 45%): approvable only after review. |
| HIGH_DTI | Debt-to-income is above the 45% cap: obligations are too high for the income. |
| LIQUIDITY_RISK | Checking under $1,000 with debt-to-income above 40%: little cushion for a missed paycheck. |
| FRAUD_REVIEW | Something on the application cannot be verified against the documents: refer it for verification. |
| UNDISCLOSED_LIABILITIES | The credit report shows debts the application does not list. |
| INCOME_VARIANCE_REVIEW | Stated income is somewhat above verified income: re-underwrite on the verified figure. |
| LIABILITY_VARIANCE_REVIEW | Bureau debts are somewhat above stated debts: re-underwrite on the bureau figure. |
| MISSING_DOCUMENT | A document the decision depends on is missing: obtain it before deciding. |

## Evidence: 20 points

The learner picks one item as the strongest evidence. It scores 20 when it carries the case's deciding value, and 0 otherwise (`keyEvidence` in `src/challenge/evidence.js`):

- a fraud twin: the document that contradicts the application (the bureau's tradelines for hidden debt, the employer verification for overstated income, the bank statement for a fabricated or altered balance);
- a near-threshold case: the field the threshold reads, on the application or on the document that shows the same value (credit score: application or bureau; checking: application or bank statement; debt-to-income: the application's ratio);
- a conflicting case: either key fact (employer verification or bureau tradelines);
- a missing document the decision depends on: "A document the decision needs is missing";
- a clean twin, or a missing document the decision does not depend on: "The evidence supports the stated figures".

The full list (a case offers only the items whose document it has): Application: stated income; Application: stated monthly debts; Application: stated checking balance; Application: stated credit score; Application: debt-to-income ratio (stated figures); Employer verification: salary; W-2: wages; Bank statement: checking balance; Bank statement: recurring debits; Credit bureau: credit score; Credit bureau: monthly obligations (tradelines); Rent verification: monthly rent; A document the decision needs is missing; The evidence supports the stated figures.

**Attempt:** REVIEW, codes UNDISCLOSED_LIABILITIES, FRAUD_REVIEW, evidence "Credit bureau: monthly obligations (tradelines)".

| Part | Working | Points |
|---|---|---|
| Decision | expected DECLINE, chosen REVIEW: matrix cell | 25 |
| Reason codes | 30 × 1/2 = 15; FRAUD_REVIEW acceptable, no penalty | 15 |

| **Total** | not passed (below 70); decision not correct | **60** |

*Gap case.* The engine decides REVIEW (FRAUD_REVIEW). The credit policy scores claimed values only: the bureau debt reaches it as a HIGH fraud alert (FR-003), so it refers for review instead of declining on the verified DTI of 47.0%. The learner is scored against the expected answer only.
