# Data Dictionary

Every field of a generated case object, organised by layer. Generated by `generateCase` in `src/core/case.js` (schema version 2.0.0, generator version 2.0.0).

## Feature-policy classes

Defined in `src/decisioning/policies/feature_policy.js` (policy version 1.0.0). The classifier works on flat feature names, not on object paths; the class given below for each field is the class the policy assigns when that field (or its flattened name) reaches a decision input.

| Class | Meaning |
|---|---|
| PERMITTED | May be read by fraud rules, the underwriting policy and models. |
| SENSITIVE | Never a decision input. Available only to fairness testing (`src/evaluation/fairness`). Names: `age`, `age_band`, `zip_code`, `region`, `geography_group`, `income_band`, `family_status_scenario`, `disability_income_scenario`, `persona`, `cost_of_living_index`. |
| PROHIBITED | Blocked from training and scoring. Identity, ground truth, labels, and anything computed from truth-vs-claim comparison. Prefixes `truth_`, `label_`, `outcome_`, `gt_` plus an explicit name list. |

Two layers are governed as a whole regardless of the name classifier: `audit_attributes` is SENSITIVE by declaration (`policy_class: "SENSITIVE"`), and `truth`, `alignment_findings`, `ground_truth_findings`, `label` and `meta` are PROHIBITED because they are, or are derived from, world truth or labels. Where the name classifier would give a different answer for an individual field (for example `zip3`, `regime`), that is noted.

Units: USD amounts are integer dollars unless stated; ratios are decimal fractions (0.38 = 38%); dates are ISO `YYYY-MM-DD` strings unless stated.
